# Frontend — Agent Guide

Read this before changing `frontend/`. It is the frontend-wide orientation; the
root `AGENTS.md` carries the mandatory rules and review gates, and
`frontend/src/README.md`, `frontend/src/queries/README.md` and `ARCHITECTURE.md`
§"Frontend structure" carry the detail. Keep this guide current when a frontend
convention changes.

Stack: Vue 3 + TypeScript + Vite, Pinia (client state), TanStack Vue Query
(server state), vue-router, shadcn-vue / Reka UI / Tailwind, `openapi-fetch` +
`openapi-typescript`, Vitest + Playwright.

## Layout (`src/`)

| Path                                                    | Responsibility                                                                                                               |
| ------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `src/api/`                                              | `client.ts` (typed `openapi-fetch` client + session middleware), `errors.ts` (`ApiError`), `generated/openapi.d.ts`          |
| `src/queries/`                                          | **All** server-state composables + `queryClient.ts` + `organisationInvalidation.ts`; `README.md` is the canonical convention |
| `src/stores/`                                           | Pinia **client** state only (`session.ts`, `organisation.ts`, `ui.ts`)                                                       |
| `src/features/auth/`                                    | Auth slice; `workos.ts` is the only WorkOS SDK importer                                                                      |
| `src/components/ui/`                                    | shadcn-vue primitives, one folder per component with an `index.ts` barrel                                                    |
| `src/components/application/`                           | Reusable app components (no barrel; imported by `.vue` path)                                                                 |
| `src/views/`, `src/layouts/`, `src/router/`, `src/lib/` | Route screens (`*View.vue`), shell layout, routes/guards, shared helpers                                                     |

Tests live beside code in `__tests__/` directories; e2e specs live in `e2e/`.

## The state boundary (most important rule)

- **HTTP happens only in `src/queries/` composables.** No Vue component or Pinia
  store imports `src/api/client.ts`. This is a documented convention, not a lint
  rule — review enforces it.
- **Pinia holds client state only; TanStack Query holds server state.** Never
  cache API data in a store.
- Query keys for org data start `['organisations', <orgId>, <domain>, …]`. The
  bare `['organisations']` root is reserved for the switch-invalidation
  predicate; platform keys live under `['platform', …]` and must not be
  invalidated by organisation switching.
- camelCase → snake_case mapping happens once inside the composable (`pageSize`
  → `page_size`). Mutations invalidate by the captured org id.
- Optimistic concurrency: update/delete send the last-read `version`; a stale
  write is a `409` (`record_version_conflict`).

`src/queries/records.ts` is the representative composable; `src/stores/organisation.ts`
the representative store.

## Generated API types

- `src/api/generated/openapi.d.ts` is generated by
  `frontend/scripts/generate-client.mjs` from `backend/openapi.json`. **Never
  hand-edit it** and never hand-write duplicate API interfaces.
- Regenerate after any API change with `make generate-client`
  (`pnpm generate:client` from `frontend/`). `make check` and the CI
  `generate-client-drift` job fail on drift, and `.prettierignore` excludes the
  generated directory.

## Auth, routing and UI

- The session token lives in `stores/session.ts`; `client.ts` attaches
  `Authorization` and `X-Org-Id` and, on `401`, clears the local session and
  WorkOS session. Boot ordering in `main.ts` is load-bearing: the router must be
  installed before WorkOS boot-restore.
- Guards in `router/index.ts`: `requiresAuth` (awaits boot restore) and
  `requiresPlatformAdmin` (reuses `meQueryOptions` via the query client).
  Protected routes are children of `AppShellLayout` and lazy-loaded.
- UI permissions come from the **selected organisation's** membership roles in
  `/me` (`src/lib/permissions.ts`), mirroring backend role bundles — the backend
  remains the enforcement point.
- Naming: views are `*View.vue` (`Platform*View.vue` for admin); `components/ui`
  uses single-word names (a lint exception), `components/application` uses
  multi-word PascalCase.

## Commands

- `pnpm type-check` (`vue-tsc --build`), `pnpm lint` (oxlint + ESLint),
  `pnpm format` (Prettier), `pnpm build`.
- `pnpm test:unit` runs Vitest in **watch** mode; use `pnpm vitest run` (or
  `make test`) for one-shot. There is no `pnpm test`. `pnpm test:e2e` /
  `make e2e` run Playwright.
- Prettier: no semicolons, single quotes, width 100.

## Testing

- Unit/component: `src/**/__tests__/*.spec.ts` (jsdom). E2E: `e2e/*.spec.ts`
  with mocks for WorkOS and `/api/v1/**`; authenticated journeys skip when
  `VITE_WORKOS_CLIENT_ID` is unset.
- Direct storage uploads are deliberately **not** generated-client calls —
  `src/lib/upload.ts` uses `XMLHttpRequest` for progress on a signed URL and
  attaches no credentials.

## Gotchas

- Regenerate the client whenever the HTTP surface changes; drift fails CI.
- Keep server state out of Pinia.
- Respect the org-scoped query-key shape; the root key is not an active key.
- No direct client import outside `src/queries/`.
- `pnpm generate:client` (package script) vs `make generate-client` (Makefile) —
  spelling differs by tool.

# Upgrading the template from v0.7 to v0.8

This guide is for a clone created from `v0.7.0` that is adopting the `v0.8.0`
release (large AI attachments and reference transfer modes). It records what
changed, how to apply it, and the manual steps that cannot be automated. See
`TEMPLATE_V0_8_SCOPE.md` for the release contract and the version convention in
`CONTRIBUTING.md` for how template releases are numbered.

`v0.8.0` is additive: no public API is broken, no existing migration is
rewritten, and the default configuration keeps the v0.7 inline-only behaviour.

## What the release adds

- Provider-neutral transfer modes (`inline`, `provider_upload`,
  `managed_signed_url`, `storage_reference`) selected from the intersection of
  source lifecycle, task, organisation policy, model/provider capability and
  deployment configuration. Above the 5,000,000-byte aggregate inline threshold,
  exactly one PDF up to 50,000,000 bytes may use a non-inline mode.
- Typed organisation policy (`allowed_transfer_modes`,
  `max_large_attachment_bytes`) on the platform AI-settings API.
- A durable `ai_attachment_references` ledger with retry-only reuse,
  expiry/deletion reconciliation and redaction guarantees.
- Provider adapters for OpenAI/Anthropic transient upload, managed signed URLs
  for retained private S3 objects, and Vertex private GCS staging.
- CLI/CI validation for task/model/provider transfer declarations.

## New dependencies

- `pypdf>=6.16.0` (runtime): provider-neutral PDF policy inspection (page count
  and structure) before a large-file transfer is allowed. It is used behind the
  AI adapter boundary; no provider SDK was added (ADR-0017).

There are no other new runtime dependencies. The transfer modes use `httpx`
(already present) and `google-auth` (already present for Vertex). Run
`cd backend && uv sync` and `cd frontend && pnpm install` after pulling.

## Configuration changes

Add the v0.8 AI settings to your environment. All non-inline behaviour is
default-deny, so the defaults below preserve v0.7 behaviour:

```dotenv
AI_ENABLED_TRANSFER_MODES='[]'
AI_INLINE_AGGREGATE_THRESHOLD_BYTES=5000000
AI_MAX_LARGE_ATTACHMENT_BYTES=50000000
AI_UPLOAD_EXPIRY_SECONDS=3600
AI_MANAGED_URL_TTL_SECONDS=900
AI_RECONCILE_BATCH_SIZE=50
AI_RECONCILE_RETRY_AFTER_SECONDS=3600
```

Enable a non-inline mode only after configuring its provider and private
staging infrastructure:

- `provider_upload`: OpenAI/Anthropic keys.
- `managed_signed_url`: retained private S3-compatible storage (minted
  just-in-time, never persisted or returned).
- `storage_reference`: `AI_VERTEX_PROJECT`, `AI_VERTEX_LOCATION`,
  `AI_VERTEX_TEMP_GCS_BUCKET` and either ADC/workload identity or
  `AI_VERTEX_CREDENTIALS_PATH`.

Production fails fast on an enabled mode whose supporting provider or settings
are missing or inconsistent. See `.env.production.example` for the full
reference and `docs/operations.md` → "AI observability and runbooks".

## Migrations

Three additive migrations ship with v0.8. Apply them with:

```bash
make migrate
# or, deliberately:
cd backend && uv run alembic upgrade head
```

| Revision | Purpose |
| --- | --- |
| `b2c3d4e5f6a7` | Organisation transfer policy columns (`allowed_transfer_modes`, `max_large_attachment_bytes`) |
| `c3d4e5f6a7b8` | `ai_attachment_references` ledger, constraints and indexes |
| `d5e6f7a8b9c0` | Provider-file reconciliation support for the ledger |

The migrations are non-destructive and add new tables/columns only. Do not
downgrade them in production to roll back application code; keep the additive
rows for roll-forward (see the rollback notes in the release plan and
`docs/backup-and-recovery.md`).

## Worker and deployment implications

- The Dramatiq worker now runs the bounded provider-file reconciliation sweep
  for expired, orphaned and deletion-failed references. It never processes
  managed URLs, GCS staging objects or feature-owned sources. Keep the worker
  and the coordinator on the same release as the API.
- The sweep uses `AI_RECONCILE_BATCH_SIZE` and
  `AI_RECONCILE_RETRY_AFTER_SECONDS`; a failed terminal deletion stamps a safe
  error code and is retried after the backoff. Alert on the cleanup backlog
  metrics documented in `docs/operations.md`.
- If you enable `storage_reference`, configure the GCS bucket lifecycle rule
  (`age = 1` day → Delete) in the Google Cloud console. Lifecycle execution is
  asynchronous and is the deployer-owned backstop; the application deletes only
  the exact AI-owned staging object it uploaded.

## Frontend client implications

`GET`/`PUT /api/v1/platform/organisations/{organisation_id}/ai-settings` gained
`allowed_transfer_modes` and `max_large_attachment_bytes`. Regenerate the
generated client so the TypeScript types match, and commit the result:

```bash
make generate-client
git diff --exit-code -- frontend/src/api/generated/openapi.d.ts
```

No hand-written frontend consumer changed: the existing platform AI-settings
view reads the regenerated schema.

## Security implications

- Caller-supplied HTTP(S) URLs remain prohibited; the feature-facing
  `AIRequest` is unchanged and cannot name a transfer mode, provider file id,
  `gs://` URI or credential.
- Managed signed URLs are minted per dispatch with a short TTL, are never
  returned/persisted/audited/logged, and are redacted at every boundary.
- Cross-organisation source/reference access is denied; database rows, broker
  messages, logs, Sentry and audit metadata never carry bytes, credentials,
  provider headers, raw responses or signed URLs.
- The platform AI-settings routes stay platform-gated and remain in the
  mandatory protected-route security matrix.

## Manual adoption steps

1. Pull the `v0.8.0` release (or merge the release branch) and run
   `cd backend && uv sync`, `cd ../frontend && pnpm install`.
2. Copy the new AI variables from `.env.example` into your environment; leave
   the transfer modes disabled unless you have configured a provider and
   infrastructure.
3. Apply the migrations (`make migrate`).
4. Regenerate the API client (`make generate-client`) and commit the diff.
5. Rebuild the worker, API and frontend containers so all three run `v0.8.0`.
6. If enabling a non-inline mode, configure the provider key/region, the GCS
   staging bucket and its `age = 1` lifecycle rule, then enable the mode and
   verify a transfer journey end-to-end.
7. Run `make check` and the relevant opt-in provider contract tests
   (`make test-ai-contracts`) in a non-production project.
